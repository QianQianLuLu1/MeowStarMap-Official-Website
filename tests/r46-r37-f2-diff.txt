结论
----------------------------------------------------------------
F2 受影响项：**只有 `sidebarLinks` 一个轴，只有 2 个单元格**
（`light|#/` 与 `light|#/identity`，均为 47 → 0）。
R47/R48/R49 对 F2 零影响；dark 遍不受影响。

为什么只有 light 遍的两个单元格
----------------------------------------------------------------
r37 的 `snapshot()` 是 `page.goto(URL + h)` 逐视图循环，同文档 hash 导航**不会重载页面**：

    light 遍： #/(全新加载) → #/identity → #/tutorial → #/dev → #/m1 → #/m1/m1p1 → #/all
               0               0             47(此处建侧栏)   130     47      47          47
    dark  遍： 同一文档继续，侧栏已建成并被缓存 → 全部 47，与基线一致

实测佐证：从 `#/all` 直接回到 `#/`，`#sidebar a` 仍为 47（状态保留），
与 dark 遍的行为一致。

另发现的环境态差异（**非本轮引入**，重落基线前需知）
----------------------------------------------------------------
`#/identity` 的 `bodyTextLen` 取决于 `localStorage.nikki_role`：

    未设角色 → 134（无「当前身份：…」行）
    role=user → 147（多一行「当前身份：用户 · 直接继续 →」）

基线里记录的是 **147**（采集时机器的 file:// localStorage 留有 role），
而 r37 每次用 `browser.new_context()` 全新上下文、不 seed role，
所以现在跑探针会得到 **134**，从而在该单元格外多报一项 `bodyTextLen` 差异。
这与 R46–R49 无关（identity 视图的渲染代码本轮零改动）。建议二选一：

    ① 重落基线时接受该项，并在签认里注明它属环境态；
    ② 在 snapshot() 前 `page.add_init_script("localStorage.setItem('nikki_role','user')")`
       把角色固定下来，让该字段确定化（改探针，需单独评审）。

R47/R48/R49 零影响的运行时证据（同一会话实测）
----------------------------------------------------------------
- 教程正文 3 张图实测：`src` 前缀 `data:image/webp;base64`、`complete=true`、`naturalWidth×Height = 1400×900`
- 同一批 `<img>` 实测带 `loading="lazy"` 与 `decoding="async"`（R48）
- 全站 `performance.getEntriesByType('resource')` **为空**（data: 内联不产生资源请求，零外链不变量在运行时成立）
- `document.fonts.check('400 16px Inter')` 与 `Noto Sans SC` 均为 true（R49）
- 依次访问 `#/m2/m2p4 → #/dev/m1 → #/all → #/` 期间 **零 pageerror / 零 unhandledrejection**
- 首屏导航计时（file://）：domContentLoaded ≈ 292 ms、load ≈ 296 ms

R47 为什么不可能影响 F2
----------------------------------------------------------------
- `imgSrcPrefix` 取 `src.slice(0, 11)` = `data:image/`，与 PNG 相同
- `imgAlts`、`modNames`、`statNums`、`docTitle`、`dlItems`、`cta`、`heroTitle` 均不读图片载荷
- `bodyTextLen` 取 `innerText`，base64 不进 `innerText`
